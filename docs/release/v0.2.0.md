# incremental-lang v0.2.0 — The Incremental Reparser

**The core, and the hard part of the roadmap.** v0.2.0 turns the scaffold into
a working incremental reparser: a document keeps a source text and its
lossless concrete syntax tree in step under edits, rebuilding only the
innermost node around each change that can safely be reparsed on its own. Every
shortcut is checked, so the tree after any edit is the tree a fresh parse would
produce. A language plugs in through one trait and a small cursor-and-builder;
the surface is ten types, and the crate depends on `syntax-lang` alone.

## What is incremental-lang?

The reparsing core an editor or language server needs. Editors reparse on
every keystroke; parsing the whole file each time costs time in proportion to
the file, while reparsing incrementally costs time in proportion to the edit.
incremental-lang owns no grammar: a language supplies a lexer and a
recursive-descent parser written against `Builder`, marks which node kinds may
be reparsed alone, and the `Document` does the rest. It is one of the
FEAT-tier crates of the `-lang` language-construction family, built on
`syntax-lang`.

## What's new in 0.2.0

### `Grammar` — a language in one trait

One kind type names both nodes and tokens. The grammar lexes, parses one node
of a requested kind, and says which kinds may be reparsed on their own — by
default none, which is always correct and never incremental. The lexer and
parser contracts are written down on the trait: tokens must tile their input,
lexing must be restartable at token boundaries, and parsing a reparsable kind
must not depend on its surroundings.

```rust
impl Grammar for Lists {
    type Kind = K;
    const ROOT: K = K::Root;

    fn lex(&self, text: &str, tokens: &mut Vec<Token<K>>) { /* ... */ }

    fn parse(&self, kind: K, b: &mut Builder<'_, K>) {
        if kind == K::List {
            return list(b); // the same function the full parse calls
        }
        b.start(K::Root);
        while !b.at_end() {
            if b.at(K::Open) { list(b) } else { b.bump() }
        }
        b.finish();
    }

    fn is_reparsable(&self, kind: K) -> bool {
        kind == K::List
    }
}
```

### `Builder` — a cursor and a tree builder in one

The grammar reads significant tokens (`peek`, `nth`, `at`, `at_end`), consumes
them (`bump`, `eat`), and shapes the tree (`start`, `finish`, and
`checkpoint` / `start_at` to wrap an operand once the operator is seen). Trivia
never reaches the grammar: the builder places it, between a node's tokens
inside the node and before a node in its parent, so every node begins and ends
on a significant token and its span is exactly its syntax. Leftover tokens and
unclosed nodes are handled, and misuse is absorbed rather than panicking, so
the tree is lossless whatever the grammar does.

### `Document` — edits in, a current tree out

`Document::new` lexes and parses once; `Document::edit` takes a byte range and
replacement text and returns a `Reparse` naming the node that was rebuilt and
the region of new text it covers.

```rust
let mut doc = Document::new(Lists, "(add (mul 2 3) 4)")?;

let edit = doc.edit(Span::new(12, 13), "30")?;   // inside `(mul 2 3)`
assert!(!edit.is_full());
assert_eq!(edit.span(), Span::new(5, 15));       // only that list was rebuilt

assert!(doc.edit(Span::new(14, 15), "")?.is_full()); // a deleted `)`: full reparse
assert_eq!(doc.tree(), Document::new(Lists, doc.text())?.tree());
```

Edits are transactional: the text and the tree are replaced together once the
new tree is complete, so a refused edit leaves the document exactly as it was,
and a panic in the grammar's own code, caught by the caller, leaves its text and
tree untouched.

### Reparsing only what is provably safe

A node is reparsed alone only if the edit lies strictly inside it, the tokens
on either side of it relex unchanged, its first and last tokens keep their
kinds, and the grammar rebuilds exactly one node of the same kind without
looking past the node's last token. That last check makes the scheme generic:
a list whose `)` was deleted keeps asking for tokens and runs off its end, so
no table of bracket pairs is needed. Unterminated strings and comments are
caught by the neighbour check. Failed attempts widen to enclosing nodes, but
never spend more than one full parse's worth of lexing before reparsing the
whole document.

### `Tree`, `Node`, `Element` — a shared green tree

The tree stores widths, not positions, in `Arc`-shared nodes, so a subtree
after the edit is still valid at its new offset and is reused untouched.
Cloning a tree is one reference-count increment; the clone never changes and
is `Send + Sync`, ready for a worker thread. When no snapshot shares the tree,
an edit updates the path to the changed node in place; while one does, the
path is copied and the snapshot is left alone. Reading goes through
positioned, zero-copy views, and `Tree::to_syntax` converts to
`syntax_lang::Node` for tooling built on the family's standard CST.

### Observability: `Reparse` and `Stats`

Each edit reports what it rebuilt; `Document::stats` counts edits served by a
single node, whole-document parses, refused attempts, and bytes lexed — enough
to tell at a glance whether a grammar's reparsable kinds are paying off.

### Examples, benchmarks, and the invariant

Three runnable examples ship — `editor` (a settings file edited keystroke by
keystroke), `diagnostics` (live syntax errors read straight from the tree),
and `snapshots` (versions handed to a worker thread, then to `syntax-lang`) —
sharing a complete JSON-with-comments grammar that doubles as the template for
wiring in a real language.

The property tests hold the central invariant: after any sequence of edits on
generated JSON, including the fragments that break lexing and balance, the
document's tree equals a fresh parse of its text, and a snapshot taken before
an edit still equals a fresh parse of the old text. A deterministic test
confirms the single-node path is genuinely taken; a soak run of 20,000 cases
per property found no divergence.

### Dependency wiring

`syntax-lang` 1 is wired: its `Token`, `TokenKind`, and `Span` are the types the
grammar contract is written in, re-exported so versions always match, and its
`Node` is the target of `Tree::to_syntax`. `parser-lang` is deliberately not
wired — its parser skips trivia, reports errors on a side channel with absolute
positions, and combines values rather than building nodes around operands,
where incremental reparsing needs a cursor fused with a tree builder that owns
trivia placement and can tell whether the grammar looked past a node's end.
The reasoning is recorded in `dev/ROADMAP.md` under the anti-deferral rule. The
scaffold's unused `serde` feature and `loom` dev-dependency were removed.

### Scaffold fixes

`Cargo.toml` had unquoted `keywords` and `categories`, so the manifest did not
parse at all; `clippy.toml` declared MSRV 1.87 against the crate's 1.85;
`deny.toml` named another project; two docs carried byte-order marks and CRLF
endings; and the README linked a `dev/DIRECTIVES.md` that does not exist. All
are fixed.

the configured CI matrix:

